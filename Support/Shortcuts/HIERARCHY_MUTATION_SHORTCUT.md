# Hierarchy Mutation Shortcut Contract

The helper Shortcut used by `remindctl` for true Apple Reminders subtask mutation must be installed in
the Shortcuts app with this exact name:

`remindctl - Mutate Hierarchy`

## Purpose

- keep EventKit as the primary path for normal top-level reminder creation
- use Shortcuts only for true Reminders parent/child hierarchy changes
- target reminders by the managed footer ID embedded in reminder notes
- keep tag mutation separate in `remindctl - Mutate Tags`

Current project commands create and tag new child reminders while they are still top-level reminders, then call
`attach_existing`. The `create_child` operation remains part of the Shortcut contract, but the CLI cannot use it for
tagged project steps until `remindctl - Mutate Tags` can resolve true subtasks by managed footer.

## Input Contract

`remindctl` sends JSON on stdin.

### Create Child

```json
{
  "schema_version": 1,
  "operation": "create_child",
  "parent_managed_id": "11111111-1111-4111-8111-111111111111",
  "child": {
    "managed_id": "22222222-2222-4222-8222-222222222222",
    "title": "Draft proposal outline",
    "notes": "Use project notes as context"
  }
}
```

Rules:

- `parent_managed_id` is required.
- `child.managed_id` is generated by `remindctl` and must be written into the child notes footer.
- `child.title` is required and non-empty.
- `child.notes` is optional.
- The Shortcut must not accept or apply due dates, priorities, or tags.
- The Shortcut must resolve the parent by the `[remindctl-gtd:v1 id=...]` footer in notes.
- The Shortcut must fail when zero or multiple parents match.
- The Shortcut must create the child as a true Reminders subtask under the parent.
- `remindctl` applies due dates, priorities, and tags outside this Shortcut.

### Attach Existing

```json
{
  "schema_version": 1,
  "operation": "attach_existing",
  "parent_managed_id": "11111111-1111-4111-8111-111111111111",
  "child_managed_id": "22222222-2222-4222-8222-222222222222"
}
```

Rules:

- `parent_managed_id` and `child_managed_id` are required.
- The Shortcut must resolve both reminders by managed footer.
- The Shortcut must fail when either side resolves to zero or multiple reminders.
- The Shortcut must move the child under the parent as a true Reminders subtask.
- Existing title, notes, due date, priority, and tags must be preserved.

## Output Contract

The Shortcut writes JSON to the caller-provided output path.

### Success

```json
{
  "success": true,
  "operation": "create_child",
  "parent_managed_id": "11111111-1111-4111-8111-111111111111",
  "child_managed_id": "22222222-2222-4222-8222-222222222222",
  "resolved_parent_count": 1,
  "resolved_child_count": 1,
  "child_is_subtask": true
}
```

Rules:

- always include `success`
- `resolved_parent_count` must be `1` for success
- `resolved_child_count` must be `1` for success
- `child_is_subtask` must be `true` for success
- if included, `operation`, `parent_managed_id`, and `child_managed_id` must echo the request
- omit `error_message` on success

### Failure

```json
{
  "success": false,
  "operation": "attach_existing",
  "parent_managed_id": "11111111-1111-4111-8111-111111111111",
  "child_managed_id": "22222222-2222-4222-8222-222222222222",
  "resolved_parent_count": 1,
  "resolved_child_count": 0,
  "child_is_subtask": false,
  "error_message": "No child reminder matched child_managed_id"
}
```

Rules:

- always emit valid JSON
- on failure, set `success = false` and populate `error_message`
- `operation`, managed IDs, counts, and `child_is_subtask` are best-effort on failure
- counts must be numbers, not text
- if a field cannot be computed, omit it rather than emitting an empty string
- do not emit human-only text outside the JSON document

## Testing

Default `swift test` validates the repo-side adapter but does not execute the installed helper.

Live hierarchy Shortcut tests are opt-in:

```bash
REMINDCTL_RUN_LIVE_HIERARCHY_TESTS=1 swift test --filter ShortcutHierarchyMutationLiveTests
```
